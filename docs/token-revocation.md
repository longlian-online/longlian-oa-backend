# Token 撤销

单 token 撤销存储 `sha256:<摘要>`，不再保存完整 JWT。全局撤销存储
`<身份类型>:user:<ID>:before:<毫秒时间戳>`，只影响同类身份在该时刻及以前签发的 token。
新 JWT 增加唯一 jti 和毫秒签发时间，避免同一秒重新登录生成相同 token；旧 JWT 的 iat 继续兼容。
无 iat 的旧凭证在存在全局撤销时按已撤销处理。

Redis 按身份类型和 ID 缓存完整撤销集合，缓存最多保留 60 秒且不超过集合最后一项的有效期。
每次命中缓存不查询黑名单表；冷缓存只按现有 `(token_type,user_id)` 索引查询一次。
读取、回填、撤销操作使用同一身份锁；写操作先清缓存，数据库事务完成后才释放锁。
这样并发请求不能把撤销前的空集合覆盖回缓存。有业务事务时参与其提交或回滚，
不额外申请连接；没有事务时为撤销写入创建事务。

Redis 读取或锁不可用时，鉴权回退数据库，不以缓存故障作为放行依据。
撤销写操作需要可用的 Redis 锁和缓存失效操作，失败时不报告登出成功，客户端应重试。
缓存更新应通过本服务完成；直接修改数据库的撤销数据后需清理相应缓存。
所有节点应保持时间同步，JWT 与截止点都使用注入的 Clock。

## 存量数据与发布

表结构、ID 和历史引用不变，无需修改或重新生成 entity。
新版本能读取历史完整 JWT 和旧全局撤销记录，缓存中始终只保留摘要或截止点。
旧的全局记录以 created_at 作为撤销截止点。

1. 停止旧版本实例并暂停登录/登出流量，避免旧版本继续写入或无法识别摘要记录。
2. 备份 token_blacklist，执行 `db/data-migrations/112-hash-token-blacklist.sql`，再启动新版本。
3. 确认 `SELECT COUNT(*) FROM token_blacklist WHERE token LIKE '%.%.%'` 返回 0。
4. 验证登出后旧 token 被拒绝、新登录正常、用户与管理员相同 ID 互不影响。

迁移可以重复执行；出现摘要和原 token 两条记录时保留较长撤销有效期。
不要直接回滚到不认识摘要和截止点的旧版本。回滚需要支持新存储格式的兼容版本，
或轮换 JWT 密钥使全部旧凭证失效后恢复旧程序。此 PR 不执行部署或修改运行中的数据库。
